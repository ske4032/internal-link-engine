From vectorto recommendation

Every page is now a point in 2048-dimensional space. Here is what happens between that and a ranked list someone can act on.

Data right now content_embedding[2048] per page, written to Neo4j
1
Runs alongside the embedding step, not after it

Graph analytics

The link structure is already fully known the moment the site is crawled — it doesn't need page text at all. So this step starts immediately, in parallel with the embedding step, rather than waiting for it. Three algorithms run over it.

PageRank internal authority, weighted by link position Leiden ×2 link graph → linkCommunityId keyword graph → keywordCommunityId Betweenness pages bridging otherwise separate clusters, computed exactly

Clustering pages by their existing links is circular. A new section has no links, so it forms no cluster, so it gets no recommendations — precisely the pages that need help most. Keyword relationships exist before any link does, so the second pass clusters on those instead.

The disagreement is the signal. Two pages in the same keyword cluster but different link clusters belong together topically and aren't connected. That gap is what the discovery stage is looking for.

1b
A third, different kind of clustering

Content clusters

The two clusterings above ask what is connected, and what we say a page is about. This one asks what a page is actually about, judged purely from its content — independent of both link structure and declared keywords.

HDBSCAN groups pages by content similarity → hubId, or −1 for pages that fit no coherent topic

That −1 label is the useful part. A page that belongs to no coherent topic is a real finding — the other two clusterings must place every page somewhere, so neither can say a page simply doesn't fit anywhere.

Two things this makes possible. Ranking which topic-to-topic connections are missing — a handful of high-value structural links rather than thousands of page-level ones. And checking whether the page a site treats as its pillar is actually the one closest to the centre of its topic.
Data now content_embedding[2048] hubId
2
Stage one · two passes

Audit what exists

Before looking for new links, score every link already on the site. Six dimensions per edge, in two passes — the first needs nothing but page structure, so it runs while embedding is still going. The second waits for it.

Pass A — no embeddings needed, runs immediately anchor quality generic? duplicated across the profile? keyword alignment does the anchor describe the target? equity efficiency source authority × position weight ÷ target need technical health 404, redirect, nofollow, noindex target Pass B — needs embeddings context relevance cosine(surrounding sentence, target vector) anchor·target fit cosine(anchor text, target page) — catches an anchor that names the right keyword but points at the wrong page
REANCHOR
Link is fine, the wording says nothing about the destination
REMOVE
No topical justification; dilutes the authority of links that earn it
FIX
Broken, redirected, nofollowed, or pointing at a noindex page
This is usually where the value is. A pillar page with forty inbound links all anchored "read more" is losing something on every one of them. That's a bigger and cheaper win than a forty-first link — and Pass A needs no machine learning at all, just pattern matching and arithmetic.
3
Stage two · three trained models

Discover what's missing

Eligibility is three hard constraints and nothing else. Indexable, not itself, not already linked.

Impressions, ranking position, page age, saturation — none of them filter anything out. They all become features the ranker weighs. A page ranking third on a valuable term still needs links to reach first, and a page ranking nowhere may be the one that needs them most.

HNSW top 50 similar pages per target, plus which topic cluster and content hub each one sits in GraphSAGE page + its neighbourhood → gnn_embedding[2048] cross-attention both pages attend to each other → pair vector LambdaMART → opportunity_score 0–100

GraphSAGE is what separates two pages with identical copy — one a pillar linked from forty places, one an orphan six clicks deep. Same content vector, very different position vector.

Data now gnn_embedding[2048] → pair vector → score 0–100
4
Shared by both stages · deterministic

Resolve the anchor

Anchor text is a ranking signal, not a copywriting problem. The keyword is the specification; the job is to find where the source page already says it.

keyword strategic primary → GSC query by opportunity value impressions × (CTR@1 − CTR@current) → title / h1 ladder 1 exact keyword in the source body → link that phrase 2 close variant (stem, plural) → link it 3 overlapping words, cheaply checked → link it 4 related in meaning, more expensive → link it 5 nothing suitable → CONTENT_GAP

No text is generated. The engine finds words already on the page and moves the link onto them. Step 3 catches most of what would otherwise need the expensive step 4 check, for a fraction of the cost. When nothing suitable exists at all, inserting a phrase would bolt a link onto copy that was never about the topic — so it reports a content gap instead, routed to whoever writes, not whoever implements links.

The type mix is a preference, not a rule. A healthy inbound profile mixes exact, partial, natural and branded anchors. That preference chooses between candidates that already exist in the copy — it is never a reason to skip a good link because the ratio wanted something else. And when comparing an anchor to the words the page already uses elsewhere, overlap is measured the same cheap way as step 3 above — meaning is the wrong yardstick for “have we said this exact phrase too many times already.”
5
Materialise and serve

One ranked queue

Neo4j SUGGESTED_ACTION edge, five action types Mongo full payload: score, signals, placements, assumptions Valkey cache invalidated → next read under 10ms

Two caps applied after ranking: no single destination appears in more than 15% of results, and no single source page contributes more than ten items. Otherwise hub pages would swallow the whole queue.

REANCHOR /blog/press-maintenance → /hydraulic-press 78

"click here"  →  "industrial hydraulic press"

The phrase is already in the linking sentence.

ADD_LINK /blog/choosing-a-press → /press-safety-2026 71

Anchor "machine guarding standards", paragraph four. Target is new with no inbound links.

FIX /hydraulic-press → /press-brake 64

Redirect chain, two hops. Point at the final URL.

CONTENT_GAP /blog/materials → /hydraulic-press 52

Topic isn't covered on the source page. Add a paragraph on machine selection to create a natural link point.

Every item carries the signals behind it and flags its own assumptions. A person decides. Nothing publishes automatically.

6
Monthly

It learns from the answer

Accept, dismiss, or edit — each writes back. Once a month three models retrain on that record.

GraphSAGE accepted pairs pulled closer in vector space LambdaMART re-ranked on graded labels, NDCG@10 anchor weights shifted toward what actually gets accepted promotion gate a new ranker ships only if it beats the current one on held-out data

That check runs automatically, and is tracked so the decision is never lost — if a retrained model doesn't clear the bar, the previous one keeps serving.

Nothing about the algorithms changes. The system gets better because it learns which recommendations this particular team says yes to.
