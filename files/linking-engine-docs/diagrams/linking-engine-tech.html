Internal linking engine

A graph + learning-to-rank system that audits a site's existing internal links and discovers the ones it's missing. Eleven stages, three trained models, one Postgres-free stack. This page walks each stage: what it computes, what it runs on, and what to expect from it.

Runtime

Estimates for a cold initial run on 8 cores / 32 GB. Every figure is projected, not measured — Prometheus step durations from the first real client replace all of it.

Site size
Two things to build in from the start. LambdaMART inference at 1.25M pairs × 3105 features is roughly 15.5 GB if assembled in one pass — it will not coexist with the Neo4j heap and the GDS projection on a 32 GB box, so stream it in ~50k chunks. And exact betweenness is O(V·E); GDS sampling brings it to minutes but changes the values, so confirm the sampled version still carries signal as a GNN feature before committing.

Things we decided not to do

Reranking stageStage 05 cross-attention is already a cross-encoder, and it's fine-tuned monthly on acceptance feedback. A general query-document reranker has never seen a linking decision, and the shape is wrong — there are no queries here, only page-to-page comparison. Revisit only if NDCG@10 plateaus and error analysis shows topical-relevance misses.
GSC eligibility filterRemoved in v4. avg_position is a mean over a heavily skewed query distribution, and the filter excluded new pages, orphans, striking-distance pages and pillars — making hub-and-spoke unrepresentable. Eligibility is not priority; the ranker decides priority and has to see the candidates to learn.
LLM anchor generationRemoved in v5. Inserting an invented phrase bolts a link onto copy that was never about the topic. Extraction only; failure emits CONTENT_GAP.
Postgres + pgvectorCollections are document-shaped with variable schema. Mongo for documents, Neo4j native HNSW for vectors, no third store.
TerraformSingle static K3s cluster. Plain hcloud scripts, ArgoCD for everything above the node.
